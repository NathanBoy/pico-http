# Security Policy

## Supported versions

| Version             | Supported |
| ------------------- | --------- |
| `main` (unreleased) | ✅        |
| `0.1.x`             | ✅        |

## Reporting a vulnerability

Please **do not** open a public GitHub issue for a security vulnerability —
that gives attackers time to exploit it before a fix ships.

Instead, email the maintainer directly at **liuhuakangk@163.com** with as much
of the following as possible:

- the affected version / commit,
- a description of the vulnerability and its impact,
- a minimal reproduction or proof-of-concept,
- any suggested fix (optional).

You should receive an acknowledgement within **48 hours**. We ask that you give
us a reasonable window (typically 30 days from first contact) to prepare and
ship a fix before publicly disclosing the issue.

## Coordinated disclosure

We believe in responsible, coordinated disclosure. Once a fix is released, we
will credit the reporter (if they wish to be credited) in the changelog.
